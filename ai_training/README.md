# Smart Energy AI Training

This workspace contains independent training pipelines for the dashboard's AI
features. Datasets are intentionally kept separate because they use different
sensors, labels, and sampling intervals.

## Energy forecasting

Train the 24-hour baseline:

```bash
python3 ai_training/src/train_forecasting.py
```

Verify the saved model:

```bash
python3 ai_training/src/predict_forecasting.py
```

Start the local dashboard API:

```bash
python3 -m uvicorn api:app --app-dir ai_training/src --reload
```

Then open `http://127.0.0.1:8000/health` or
`http://127.0.0.1:8000/predict/energy`.

The Flutter dashboard uses `/predict/summary`, which combines the independent
model results and derives balance depletion and recommendations. Energy cost is
calculated with the versioned Sri Lankan progressive-block tariff under
`tariffs/`; depletion is simulated day by day across billing-block boundaries.
Recommendations are deterministic rules over model outputs; they are not
generated by a language model.

## Persistent meter data

The API persists sampled readings, meter account state, and recharges. It uses
Firestore when Google credentials are configured and otherwise falls back to
`ai_training/data/smart_energy.db`. The fallback is useful for local
development and survives API restarts.

Install the server dependencies:

```bash
python3 -m pip install -r ai_training/requirements.txt
```

For Firestore:

1. Create a Firebase project and enable Firestore.
2. In Firebase Console, open **Project settings → Service accounts** and create
   a private key.
3. Store that JSON outside this repository.
4. Start the API with:

```bash
GOOGLE_APPLICATION_CREDENTIALS='/absolute/path/to/service-account.json' \
FIREBASE_PROJECT_ID='your-project-id' \
PERSISTENCE_BACKEND='firestore' \
TARIFF_ADMIN_KEY='your-private-admin-key' \
DEVICE_API_KEY='your-private-device-key' \
python3 -m uvicorn api:app --app-dir ai_training/src --reload
```

Never commit the service-account JSON. `firestore.rules` denies direct client
access because meter data is accessed through the server. The API samples
Firestore writes every 30 seconds by default to control cost. Override this
with `PERSISTENCE_SAMPLE_SECONDS`.

Verify the active backend:

```bash
curl http://127.0.0.1:8000/health
```

The response reports `persistence.backend` as `firestore` or `sqlite`.
Usage History reads persisted aggregates from
`/devices/EM-2048/usage`.

Generated artifacts:

- `models/energy_forecast_24h.joblib`
- `reports/energy_forecast_metrics.json`
- `reports/energy_forecast_report.md`

The forecasting source currently lacks a calendar date. The pipeline uses
sequential order and time-of-day but excludes weekday and seasonal features.

## Abnormal usage detection

```bash
python3 ai_training/src/train_anomaly.py
```

This produces `models/anomaly_detector.joblib` and the anomaly evaluation files
under `reports/`. Its Kaggle inputs are pre-normalized; real ESP32 readings will
need calibrated normalization before operational use.

## Appliance category detection

```bash
python3 ai_training/src/train_appliance.py
```

The first run extracts bounded 60-second features into
`datasets/appliance_window_features.csv`. Entire smart-plug devices are held out
from training to reduce identity leakage.

## Safety models

```bash
python3 ai_training/src/train_safety.py
```

This trains independent smoke/fire, electrical power-quality, and gas-identity
models. Gas identity is not presented as leak probability because the public
dataset has no clean-air class.
